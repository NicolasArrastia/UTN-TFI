# 8. Riesgos

| Riesgo | Impacto | Mitigación |
|---|---|---|
| Aumento del alcance | No completar el MVP a tiempo | Mantener el alcance definido y pasar nuevas funcionalidades a futuras versiones |
| Dificultades con autenticación/autorización | Demoras en backend e integración | Implementarlas desde las primeras etapas y probarlas progresivamente |
| Mayor complejidad de las estadísticas | Demoras en el dashboard | Comenzar por los indicadores definidos para el MVP |
| Problemas de integración frontend/backend | Errores y demoras | Definir previamente la API e integrar progresivamente |
| Diferencias entre tipos de comercios | Algunas funciones podrían no adaptarse | Mantener el MVP centrado en operaciones comunes |
| Demoras en etapas planificadas | Menor tiempo para pruebas y entrega | Revisar avances y priorizar funcionalidades indispensables |

## Estrategia general

El principal mecanismo de reducción de riesgo será mantener controlado el alcance. Las funcionalidades no indispensables no se incorporarán al MVP aunque puedan resultar interesantes para versiones futuras.
